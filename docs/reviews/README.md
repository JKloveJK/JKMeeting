# 技术方案评审记录

每项技术方案必须在编码前完成一次独立对抗评审。评审记录文件名为：

```text
YYYY-MM-DD-<topic>-review.md
```

## 模板

```markdown
# <需求名称>技术方案评审

- 日期：YYYY-MM-DD
- 评审角色：独立评审 agent
- 关联需求：<requirements 路径>
- 关联方案：<plans 路径>
- 评审范围：需求覆盖、架构边界、风险、可测试性、实施步骤

## 第一阶段：问题清单

| 级别 | 问题 | 证据或定位 | 要求的修订 |
| --- | --- | --- | --- |
| 阻塞 / 高 / 中 / 低 |  |  |  |

## 方案修订核对

| 问题 | 修订位置 | 核对结果 |
| --- | --- | --- |
|  |  | 已解决 / 未解决 |

## 结论

通过 / 不通过。

- 通过：允许开始编码，并列出实施阶段必须复验的风险。
- 不通过：停止编码，列出需要用户决策的阻塞项。
```
