# 架构决策记录（ADR）

本目录保存会影响多个阶段、多个模块或后续学习判断的技术决策。它不记录普通实现细节，也不替代代码注释。

## 何时创建 ADR

满足任一条件即创建：

- 影响跨模块 API、数据模型、状态机或运行拓扑。
- 在两个以上合理方案之间做取舍，且理由未来可能遗忘。
- 引入或排除重要依赖、外部服务、数据/隐私策略。
- 结论将影响 P0 之后的阶段、指标或成本。

普通局部修复不创建 ADR；实验数据应放到 `docs/reports/`，并在 ADR 或 `docs/metrics.md` 中引用。

## 命名与状态

文件名：`NNNN-<topic>.md`，编号递增且不复用。状态使用“已接受 / 已替代 / 已废弃”。

## 模板

```markdown
# NNNN：<决策标题>

- 日期：YYYY-MM-DD
- 状态：已接受
- 关联：<路线、设计、指标或报告路径>

## 背景

要解决的问题与约束。

## 决定

明确选择什么，不选择什么。

## 依据

证据、对比或可复现验证。

## 后果

得到什么、承担什么代价、哪些条件下重新评估。
```
