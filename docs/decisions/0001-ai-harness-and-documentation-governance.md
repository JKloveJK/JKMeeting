# 0001：采用最小 AI Harness 与分层文档治理

- 日期：2026-09-29
- 状态：已接受
- 关联：`AGENTS.md`、`docs/客户端全栈学习路线.md`、`docs/plans/2026-09-29-p0-minimal-loop-design.md`、`docs/metrics.md`

## 背景

JKMeeting 的目标不仅是完成会议语音助手，更是通过真实项目学习跨平台 C++、Go 服务端、音视频和 Agent 工程能力。若 AI 以“最快跑通”为目标，可能通过重型依赖、过度 mock 或跳过测试与测量，削弱项目的学习价值和可迁移证据。

项目当前仅有路线与阶段设计，需要一个足够轻量的协作契约来约束范围、模块边界、验证方式和文档更新，而不在 P0 引入复杂流程或额外平台。

## 决定

1. 以仓库根目录 `AGENTS.md` 作为 AI 与人协作的唯一项目级 Harness。
2. 每次变更必须声明阶段目标、非目标、验证方式和证据；未经证据支持的推断不能作为结论。
3. P0 只做最小端到端闭环，严格遵循已有的范围护栏与 core/壳层边界。
4. 以 `Makefile` 作为验证命令入口；代码模块出现后逐步补全对应的真实测试、smoke、压测和端到端目标。
5. 以 `docs/metrics.md` 保存性能和质量基线，以 ADR 保存影响后续模块的技术取舍。
6. 文档按层次维护：项目级路线/指标/决策始终更新；模块仅在拥有公开契约、独立状态机、数据模型、运行拓扑或运维要求时增加模块文档。

## 依据

现有路线已明确“约束驱动深度”：服务端依赖加压与观测，音视频依赖指标化，Agent 依赖可评测，Android 依赖双端对比。P0 设计也已定义范围护栏、独立验证顺序和四项基线。最小 Harness 只把这些已有原则固化为协作与记录规则，不新增业务功能和运行依赖。

## 后果

- 实现速度会增加少量验证与记录成本，但每项学习结论可复现、可解释。
- 后续新增功能必须检查受影响文档，避免路线、实现与指标脱节。
- 不为局部代码创建文档，避免文档膨胀；跨模块决策和可测量结论必须留痕。
- 若 P0 的契约阻碍真实实现，可通过新增 ADR 明确修改原因与替代规则，而不是隐式绕过。
