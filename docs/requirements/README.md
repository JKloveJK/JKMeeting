# 需求文档

每个需要编码的新需求在本目录创建一份需求文档，文件名为：

```text
YYYY-MM-DD-<topic>-requirements.md
```

## 模板

```markdown
# <需求名称>

- 日期：YYYY-MM-DD
- 状态：草稿 / 已确认 / 已实现 / 已验收
- 关联：<路线、ADR、指标或需求链接>

## 背景与问题

为什么需要做这项需求；当前行为、痛点或可观察事实是什么。

## 目标

可验证的用户或工程结果。

## 范围

本需求包含的能力和模块。

## 非目标

明确本次不做的能力，防止范围扩张。

## 约束与依赖

平台、性能、隐私、兼容性、已有接口、外部服务和数据依赖。

## 验收标准

逐条列出可测试的成功判据及证据类型。

## 待确认问题

在开始技术方案前必须由用户确认的问题；无则写“无”。
```
