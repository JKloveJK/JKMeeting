# P5 工程化与轻量实时流需求

- 日期：2026-10-29
- 状态：已实施（本机口径，见 [P5 报告](../reports/2026-10-29-p5-engineering-realtime-report.md)）；CI 待远端首跑
- 路线：[客户端全栈学习路线 · P5](../客户端全栈学习路线.md)
- 用户已确认（2026-10-29）：工程化全量 + 轻量实时音频流（WebSocket 推流 + 抖动缓冲，本机可测丢包）；**不引入 WebRTC 大型依赖、不做视频**。

## 范围

### 工程化

1. CI：提交即跑 core 单测、Go 单测、Android 构建与 JVM 单测；本地以 `make p5-ci` 复现同一门禁子集。
2. 监控告警：Prometheus 抓取既有 `/metrics`，附告警规则（API 错误率、Outbox 积压、转写失败）；本地 Compose 可选 profile 启动，不改变默认拓扑。
3. 成本台账：把 P3 的 token 记账口径沉淀为固定条目写入指标台账（本地推理按 GPU 秒计，外部单价仅作假设换算并注明）。
4. 不停机迁移演练（L5）：一次 expand/contract 演练——新增可空列 + 双写/回填脚本 + 收缩说明，附回滚路径，全程服务不中断的验证记录。

### 轻量实时流

5. C++ core 新增纯计算 `JitterBuffer`：按序号入队、乱序重排、丢包以静音填充、输出 20 ms 帧；纯单测覆盖乱序/丢包/迟到。
6. 服务端 WebSocket 推流端点：客户端按 20 ms 帧推送 PCM（序号 + 时间戳），服务端经抖动缓冲后统计首帧延迟与丢包恢复；本机回环 + 人工丢包注入验证。

## 非目标

- WebRTC / SRT、视频、FFmpeg 交叉编译、K8s、灰度发布平台（路线已明确后置）。
- Android/Apple 客户端的实时推流 UI（本轮只做 core + 服务端链路与协议验证）。
