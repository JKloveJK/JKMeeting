# P0 Apple 客户端与 ASR 闭环需求

- 日期：2026-09-30
- 阶段：P0 步骤 5、6；用户已确认现有录音可用，要求在 App 中看到转写功能入口与结果。
- 已确认边界：用户允许 Mac 的本地 HTTP API 与 S3 端口在同一局域网供 iPhone 访问；仅用于开发环境，不对公网开放。固定 Bearer token 只从运行环境提供，不能写入 App 源码、plist、工程配置或日志。

## 背景与目标

现有 Apple App 仅有本地录音与播放，服务端独立脚本已验证真实 m4a 上传、异步转写与文本持久化。目标是在录音成功后由用户明确触发上传转写，能看到上传、等待转写、完成文本或错误，并保留本地回放与失败重试。P0 同时要求前台录音最多 5 分钟及可见的中断收尾；真机端到端验收与四项指标不得用单测替代。

## 范围与验收

1. iOS/macOS 的录音页在保存后显示“上传并转写”入口，录音中仍能停止；明确展示未配置、上传、等待转写、成功文本、失败与重试状态。重新录音或页面销毁时不允许旧任务更新新录音的界面。
2. 复用现有四个 Go 接口：创建（duration_ms、size_bytes、audio/mp4）、用服务端原样返回的预签名 URL PUT 文件字节、complete、有限轮询查询至 done/failed；API 请求才带 Bearer，预签名 URL 不带。服务端回放 URL 可用于下载验证，但刚录制的音频优先本地回放，不强制重复下载。
3. 失败保留本地文件；网络超时、取消、非 2xx、非法响应与上传成功但 complete 结果不明均给可诊断的错误；重试时避免误将原状态重新 complete。不得记录 token、预签名 URL 的 query 或转写文本。禁止请求非预期上传主机、scheme 或端口。
4. 本地 HTTP 仅开发使用；API 地址、S3 主机和 token 不写死。真机所获预签名 URL 必须由服务端用手机可达的主机签发，不在客户端替换 Host；配置环境及网络权限需明确验证。不会自动启动服务或发送音频，点击按钮才上传。
5. 录音达到 5 分钟后自动走与用户停止相同的落盘回读路径，并显示时限原因；系统中断时同样收尾，保留有效文件，不制造空成功记录。权限拒绝给出设置引导。
6. 双端共享 XCTest 覆盖协议顺序、PUT 内容/头、状态/失败/重试/取消、录音限时与中断；运行与受影响模块匹配的 Makefile 验证。真机 30 秒录音、回放、显示转写和四项性能基线需留原始证据，未做时明确标为待验收。

## 非目标

不增加登录/多用户、云服务/外部模型、后台录音、实时流、摘要/RAG/MCP、Android、HTTPS 或新服务端 API；不修改数据库 schema、C++ core 公共接口，不自动上传用户音频。

## 依赖与待验收

依赖本机 PostgreSQL、Redis、SeaweedFS、Go API/Worker 与 whisper.cpp 正常启动，Mac/iPhone 与签名用 S3 主机互通。手机 Wi-Fi/防火墙/麦克风授权及真机指标需用户在设备上配合；未经设备实测不声明 P0 完成。
